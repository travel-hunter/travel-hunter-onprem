## 1. 저장된 행 - 마이그레이션 `0055_policy_text_notation`

- 대상: 주민증 · 숙박세일 · 교통 · 반값여행 정책 중 `admin_override_enabled` 가 아닌 행(숨김 포함). 칸은 `structured_detail` 안 문자열과 `target_condition`.
- 1~4번: (옛 글자 → 새 글자) 쌍을 마이그레이션 안에 고정해 적용한다.
- 5번(반값여행 잘린 괄호): 조각 일부가 빠지거나 다른 칸에 들어가 있어 이어 붙이면 틀린다. 그래서 잘린 조각이 있는 행은 고친 매퍼로 기록에서 다시 만든다(0045 처럼 지금 매퍼를 import). 기간(`periods`)을 뺀 칸을 바꾸고, 기간은 저장값을 둔다. 지금 매퍼가 옛 행의 '여행 기간' 을 다시 만들지 못하는 경우가 있다. `target_condition` 은 그것도 잘렸을 때만 바꾼다. 잘림 판정은 괄호 깊이(닫는 괄호가 먼저 나오거나 끝에서 안 닫힘)로 한다.
- 바뀐 행만 `updated_at`. downgrade 는 아무것도 안 한다(글자 교정이라 되돌릴 이유 없음).
- 수집 기록은 그대로 → 지문이 안 바뀌어 검토 후보가 안 생긴다. 다음 승인 승격도 새 코드로 같은 글자를 만든다.
- 범위 밖: 교통 `policy_comment` · `description` 은 수집 원문을 그대로 옮긴 값이라 "운임료" · "(89개)" 가 남는다(다음 승격 때 원문으로 다시 써진다). 상세 화면은 이 줄을 안 쓰고, 신청한 혜택 목록(`AppliedPolicyLinksPage`) 요약에만 보인다.

## 3. 위험

- 글자 일치로만 바꾸므로 옛 판 행은 남을 수 있다 → 로컬 실행 뒤 남은 행 수를 센다.
- 개발서버 DB 판이 로컬과 다를 수 있다 → 배포 **전** 개발서버에서 `planned_changes` 로 행마다 저장값과 새 값을 칸별로 비교한다(읽기, 승인 뒤). 반값여행을 다시 만들 때 기록의 지금 raw_payload 를 쓰므로, 차이가 조각 잇기뿐인지 본다. 배포 뒤 옛 표기 남은 행 0 을 같은 SELECT 로 확인.
- 0055 는 매퍼를 import 한다(0044 · 0045 · 0053 과 같음). 나중에 매퍼가 그 뒤 마이그레이션에서 생긴 열을 읽게 되면 0055 전 판 DB 를 올릴 때 멈출 수 있다.
