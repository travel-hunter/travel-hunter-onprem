# 정책 탭 — 뒤로가기 복원과 지도→목록 한 페이지 모션

**Goal 1:** 정책 카드·장소 카드에 들어갔다 뒤로 가면 **직전 화면 그대로** 돌아온다(지금은 지도 홈으로 초기화).
**Goal 2:** 아래에서 올라오는 목록이 "서브창"이 아니라 **한 페이지가 위로 붙는** 모션이 된다. 검색창 바로 아래에 멈추고, 색이 이어져 경계가 안 보이며, 내릴 때는 스크롤 속도·힘에 따라 지도로 되돌아간다.

**사용자 결정(2026-09-19 질문 답변)**
- 복원 범위: **화면 상태 전부**(고른 지역·목록/지도·서브창 열림). 새로고침·북마크에도 같은 화면.
- 지도: **제자리에 그대로**. 올라오는 페이지가 아래에서부터 지도를 점점 가리고, 다 올라오면 서브창이 아니라 온전한 페이지로 보인다.
- 탭바: 갑자기 없애지 않는다. 올라오는 **페이지 위쪽 모서리 뒤로** 가라앉으며 서서히 옅어져 사라진다(2026-09-19 추가 지시).
- 페이지가 검색창 밑에 붙으면서 경계선 없이 한 색으로 합쳐진다.
- 검색창: **고정**, 올라온 페이지가 그 바로 아래에 멈춘다.
- (가정) 페이지를 다시 내려 지도로 돌아오면 **탭바는 복귀**한다 — 없으면 다른 탭으로 못 간다. 아니라면 알려주면 바꾼다.

## 원인 — 왜 뒤로가면 지도 홈인가

`PolicyPages.tsx`의 `mapRegion`(고른 지역)·`mapView`(지도/목록)와 `PolicyMapSheet`의 `open`이 **React 상태**다. 필터(`category`·`region`·`period`·`amount`·`saved`)만 URL에 있어 살아남고, 나머지는 상세로 이동했다 돌아오면 초기값(지도 홈)으로 다시 만들어진다.

## Task 1 — 화면 상태를 URL로

`frontend/src/pages/PolicyPages.tsx`

| 상태 | URL 키 | 값 | 히스토리 |
|---|---|---|---|
| 고른 지역 | `place` | 시도명(`전남`) | push — 뒤로가기로 지도 복귀 |
| 목록/지도 | `view` | `list` (기본 `map`은 키 생략) | push |
| 서브창 열림 | `sheet` | `1` | **replace** — 여닫을 때마다 히스토리가 쌓이면 뒤로가기를 여러 번 눌러야 한다 |

- 필터가 이미 쓰는 `region` 과 겹치지 않게 **`place`** 를 쓴다(지도 선택은 필터가 아니다 — 9/16 결정).
- `useState` → `searchParams` 파생 + `setSearchParams`. 기존 `writeFilterParams` 옆에 `writeViewParams(next, { replace })` 를 둔다.
- `PolicyMapSheet` 의 `open` 은 상위에서 `open`/`onOpenChange` 로 받는다(제어 컴포넌트). 시트 안 타일 상세(`openKey`)는 URL에 넣지 않는다 — 한 단계 더 깊은 임시 상태다.

검증: 지역 클릭 → 표시 → 카드 진입 → 뒤로 → **목록 그대로**. 한 번 더 뒤로 → 지도. 새로고침해도 같은 화면.

- **Task 2 설계 확정(2026-09-19)** — 아래 표를 이렇게 구현한다.
  - 진행도는 `document.body` 의 `--thmap-progress`(0~1) 한 개. 리렌더 없이 JS 가 값만 쓰고
    나머지는 전부 CSS 가 읽는다. 시트 밖 요소(탭바)도 같은 변수를 상속으로 읽는다.
    정책 탭을 떠나면 effect 정리에서 변수를 지운다 - 다른 탭 탭바가 영향받지 않게.
  - 시트는 `bottom: 0`, `z-index: 95`(탭바 90 위), 높이 `100dvh - top`.
    닫힌 자리 `--thmap-closed-y: calc(100% - 20px - var(--thmap-tabbar))` 로 두어
    p=0 에서도 손잡이 20px 이 탭바 **위**에 남는다.
  - 끌고 있는 동안은 `body.thmap-dragging` 으로 시트·딤·탭바의 transition 을 같이 끈다
    (시트에만 걸던 `.thmap-drag` 대체 - 탭바가 따로 놀면 안 된다).
  - 딤은 없애지 않고 중간에서만 옅게 뜨게 한다: `p·(1-p)·2.4` (p=0·1 에서 0).
    바깥 클릭으로 닫는 자리가 딤이라 요소 자체는 남긴다.
  - 배경 합치기는 `color-mix(in srgb, var(--surface-app) p%, var(--color-bg-card))`.
    검색창이 있는 `.prototype-policy-list-screen` 바탕색이 `--surface-app` 이다.
  - 속도 판정: 시트가 움직인 px / 경과 ms. **0.6 px/ms 를 넘고** 이동이 전체 거리의 15% 를
    넘으면 절반 전에도 방향대로 확정한다. 15% 문턱이 없으면 휠 한 칸(순간 속도가 늘 크다)에
    닫혀 버린다. 느리면 종전대로 절반 규칙.
  - `.bottom-tabs` 의 기본 규칙은 `app.css` 에서 고친다 - `policy-map.css` 는 PolicyPages 에서
    import 라 빌드 순서가 보장되지 않아 같은 특이도 덮어쓰기가 위험하다.

- **Task 2·3 완료(2026-09-19)** — 진행도 모델로 갈아끼웠다. 시트가 픽셀 transform 을 직접 쓰던 것을
  `--thmap-progress` 하나로 바꾸고, 시트 위치·모서리(24→0)·그림자·바탕색·손잡이·딤·탭바가 모두 그 값을 읽는다.
  - 닫는 판정: 절반 규칙 + **빠르게 내리면 30% 에서 확정**. 휠은 한 칸이 통째로 도착해 순간 속도가
    늘 크므로 속도(px/ms) 대신 `220ms 안에 30%` 로 본다. 손잡이 끌기는 실제 손가락이라 속도(0.6px/ms)를 쓴다.
  - 시트 `bottom: 0`·`z-index: 95`(탭바 90 위), 닫힌 자리에서만 탭바 높이를 빼 손잡이가 탭바에 안 가린다.

  1. *프레임이 떨어짐* — 세 가지를 고쳤다. (a) 진행도 변수를 `body` 에 쓰면 한 프레임마다 문서

     (b) 모서리·배경색·그림자는 다시 칠해야 하는 속성이라 진행도에서 떼어 `.thmap-open` 클래스로
     옮겼다 - 끄는 동안 매 프레임 바뀌는 건 transform·opacity 뿐이다. FAB 의 `bottom` 계산도 상수로

     통째로 다시 흐리느라 가장 비쌌다. 흐림 대신 불투명 배경(미지원 브라우저가 쓰던 모습).

     속도 규칙을 걷어냈다. 중간(0.5)을 **건너간** 순간에만 끝까지 붙고, 건너기 전에는 손을 뗀
     자리에 선다. 끝 여유 8% 는 그 끝으로 **다가갈 때만** 본다(끝에서 출발할 때도 보면 스프링백이
     그대로 되살아난다). 멈춰 선 자리에서 지도가 보여야 하므로 딤을 절반으로 낮췄다.
     모바일 답변("중간까지 내리는 게 수월해야")에 맞춰 **목록 맨 위에서 아래로 끌면** 어디를 잡든

     없던 것이 불편의 실제 원인이었다.
     함정 하나: 끌던 도중 확정하면 `open` 이 바뀌며 effect 가 다시 걸려 지역 변수로 둔 끌기 상태가

## Task 2 — 진행도 하나로 묶은 한 페이지 모션

지금은 `.thmap-sheet` 가 `translateY(100% - 20px)` ↔ `translateY(0)` 두 상태를 오가고, 딤·둥근 모서리·그림자·손잡이가 늘 "창"처럼 보이게 한다.

**진행도 `p`(0=지도, 1=페이지)를 CSS 변수 하나로 만들고 모든 표현을 거기에 건다.**

`frontend/src/components/map/PolicyMapSheet.tsx`
- `p` 를 ref+CSS 변수로 관리(리렌더 없이). 휠·포인터 이동량을 `p` 에 더한다.
- 놓는 순간 판정: **속도 우선** — 최근 이동 속도가 임계(≈0.6 px/ms)를 넘으면 방향대로 0 또는 1로, 느리면 `p > 0.5` 기준. 지금의 "절반" 규칙을 속도로 보완한다(요구: 속도와 힘에 따라 롤백).
- 수렴은 스프링(`cubic-bezier(0.22, 0.61, 0.36, 1)`, 0.42s) 유지. 손을 떼기 전에는 손가락/휠을 그대로 따라간다.

`frontend/src/styles/policy-map.css` — `p` 에 따라 한꺼번에 변한다
| 표현 | p=0 | p=1 |
|---|---|---|
| 세로 위치 | 검색창 아래 화면 밖(손잡이만 20px) | 검색창 바로 아래(`--thmap-sheet-top`) |
| 모서리 | 24px | **0** |
| 그림자 | `0 -14px 34px` | **없음** |
| 손잡이(`.thmap-grab`) | 보임 | **투명** |
| 배경 | 카드색 | **검색창 영역과 같은 색**(`--surface-app`) |
| 딤 | 0.38 | **0** |
| 탭바 | 제자리 · 또렷함 | 아래로 가라앉아 사라짐(`translateY(p×100%)` + `opacity 1→0`), 올라오는 페이지가 그 위를 덮는다 |

- 탭바는 `AppLayout` 소유라 정책 탭에서만 움직여야 한다. `body`(또는 `.app-container`)에 `--thmap-progress` 를 쓰고 `.bottom-tabs` 가 그 값을 읽는다. 정책 탭이 아니면 변수가 없어 기본값 0.
- **쌓임 순서를 뒤집는다.** 지금은 탭바(z-index 90)가 시트(70) 위에 있고 시트가 탭바 높이에서 멈춘다(`bottom: var(--thmap-tabbar)`).
  페이지가 탭바를 덮으려면 정책 탭에서 시트가 탭바보다 위에 오고 `bottom: 0` 까지 내려가야 한다. 탭바는 그 아래에서 가라앉는다.
  주의: 시트가 닫힌 상태(p=0)에서는 손잡이가 탭바에 가리지 않아야 한다 - 손잡이 높이만큼은 탭바 위로 남긴다.
- "선이 안 보이게" — 검색창 영역(`.prototype-policy-list-screen` 상단)과 올라온 페이지가 같은 배경을 쓰고, p=1에서 경계선·그림자를 모두 0으로.
- `prefers-reduced-motion` 에서는 전환 없이 즉시 0/1.
