# 지도 크기 - 규격을 타지 않는 구조로

## 왜 계속 문제가 생기나

크기를 정하는 곳이 **세 군데로 흩어져 서로 싸우고 있다.**

| 어디 | 무엇을 정하나 | 단위 |
|---|---|---|
| `regionMapEngine.ts` `SEA_PAD` | viewBox 좌우 바다 여백 | SVG 단위 |
| `PolicyRegionMap.tsx` `fitHeight` | host 픽셀 높이 (`width / aspect * ZOOM_MAX`, `available` 로 클램프) | px |
| `policy-map.css` | 칸 높이, `justify-content: center`, `HINT`, 꼬리 그림자 | px |

세 값이 **순환한다**: `SEA_PAD` 를 키우면 aspect 가 커지고 → `natural` 이 작아지고 →
세로가 다시 비어 → `ZOOM_MAX` 를 올리면 → 좌우가 잘린다. 한 쪽을 맞추면 다른 쪽이 깨진다.
지금까지 고친 것이 전부 이 순환의 한 지점을 손본 것이라 기기 비율이 바뀔 때마다 재발한다.

증상 이력: 세로 여백(letterbox) → slice 로 채움 → 좌우 땅 잘림(-9px) → 여백 키움 → 다시 세로 빔.
추가로 SVG 안 바다와 칸 배경의 경계가 가로선으로 드러난다(host 바닥 ≈ y728, 칸 바닥 757).

## 고칠 방향 - 픽셀 계산을 없앤다

**칸 비율에 맞춰 viewBox 를 늘린다.** 땅의 배율은 고정하고, 남는 쪽은 바다가 채운다.
`meet` 이냐 `slice` 냐를 고를 필요 자체가 사라진다 - viewBox 비율 = 칸 비율이면 둘이 같다.

```
land  = 땅만의 bbox (독도·잔물결 제외, 지금 fitVB 가 이미 구한다)
pad   = 땅 폭 기준 최소 바다 (예: 좌우 8%, 위 RISE+2, 아래 DEPTH+3)
want  = { w: land.w + pad*2, h: land.h + padTop + padBottom }
box   = host.clientWidth / host.clientHeight        // 칸의 실제 비율
if (want.w / want.h < box) want.w = want.h * box    // 가로가 모자라면 바다를 좌우로
else                       want.h = want.w / box    // 세로가 모자라면 바다를 위아래로
VB = want 을 land 중심에 맞춰 배치
```

이러면 어떤 규격에서도 **동시에** 성립한다:
- 땅이 잘리지 않는다 (최소 여백이 늘 살아남는다)
- 빈 띠가 없다 (viewBox 비율 = 칸 비율이므로 letterbox 0)
- 바다가 칸을 꽉 채운다 (SVG 배경 rect 하나가 전부 그린다 → 안팎 경계선도 사라진다)
- 좁고 긴 화면일수록 위아래 바다가, 넓은 화면일수록 좌우 바다가 자동으로 넓어진다

## 무엇을 지우고 무엇을 남기나

**지운다** - `ZOOM_MAX`, `preserveAspectRatio="slice"`, `fitHeight` 의 `natural` 계산,
`SEA_PAD` 의 고정 단위 성격(→ 땅 폭 대비 비율로 바꾼다).

**남긴다** - 칸 높이 계산(탭바·시트를 피하는 부분), 꼬리 그림자, `HINT`.
`host` 는 칸을 100% × 100% 로 채운다. 가운데 정렬도 필요 없어진다 - viewBox 가 이미 가운데다.

**다이얼은 하나만 남는다**: `SEA_MIN_PAD` (땅 폭 대비 바다 최소 여백, 예 0.08).

## 손봐야 하는 것

1. **리사이즈**: viewBox 가 칸 비율에 걸리므로 회전·창 크기 변화에 다시 계산해야 한다.
   `ResizeObserver` 로 host 를 보고 `fitVB()` 재호출. 지금은 최초 1회뿐이다.
2. **잔물결**: 지금 `build()` 안에서 추정 VB 로 그린다. VB 가 바뀌면 자리도 바뀌어야 하므로
   `fitVB()` 뒤로 옮기고 리사이즈 때 다시 그린다. 시드가 고정이라 같은 규격이면 늘 같은 자리다.
   연속 리사이즈에 다시 그리는 비용이 있으니 디바운스(≈120ms).
3. **jsdom**: `getBBox` 도 `clientWidth` 도 없다(0 을 준다). 칸 비율을 못 구하면
   지금의 추정치 경로를 그대로 쓰도록 폴백을 남긴다. 테스트 379 개가 이 경로를 탄다.
4. **히트 테스트**: `getScreenCTM` 기반이라 viewBox 가 바뀌어도 그대로 맞는다. 손댈 곳 없다.

## 검증

- 390×844, 360×640, 430×932, 768 이상 데스크톱 넷에서: 땅 좌우·상하 여백 ≥ 0,
  칸 안에 빈 띠 없음, 스크롤 0, 지도 top 이 스크롤로 안 움직임
- 세로/가로 회전 후에도 위 항목 유지
- `vitest run` 379 통과, `tsc` 통과

## 하지 않는 것

- 확대/축소·팬 같은 조작 추가. 지금 요구는 "어떤 기기에서도 알아서 맞을 것" 하나다
- 지도 데이터 교체

## 구현 결과 (2026-09-11)

계획대로 적용했다.

- `SEA_PAD = 50`(고정 단위) → `SEA_MIN_PAD = 0.05`(땅 폭 대비 비율)
- `preserveAspectRatio="slice"` 삭제, `ZOOM_MAX` 삭제, `fitHeight` 의 `natural` 계산 삭제
- `fitVB()` 가 `host.clientWidth / clientHeight` 를 읽어 모자란 쪽을 바다로 늘린다
- 잔물결을 `build()` 에서 `fitVB()` 끝으로 옮기고 매번 `replaceChildren()` 으로 다시 심는다
- `handle.resize()` 추가, `ResizeObserver`(디바운스 120ms)로 칸을 감시
- 칸을 못 재는 환경(jsdom)은 추정 viewBox 를 그대로 쓰는 폴백

**다섯 규격 측정** (칸 비율 = VB 비율, 땅 여백은 왼/오/위/아래 px)

| 규격 | 칸 | 비율 일치 | 땅 여백 |
|---|---|---|---|
| 실제 폰 390×844 | 375×569 | 0.659 = 0.659 | 22 / 17 / 62 / 56 |
| 좁고 짧음 | 320×560 | 0.571 ≈ 0.572 | 26 / 22 / 100 / 95 |
| 넓고 김 | 430×700 | 0.614 ≈ 0.615 | 35 / 30 / 108 / 101 |
| 가로 눕힘 | 760×300 | 2.533 = 2.533 | 280 / 277 / 15 / 11 |
| 데스크톱 | 1100×700 | 1.571 = 1.571 | 317 / 309 / 35 / 27 |

어느 규격에서도 땅이 잘리지 않고(여백 전부 양수), 빈 띠가 없고, 파도는 45개를 유지한다.
스크롤 0, 지도 top 고정. 하단 가로선(SVG 안팎 바다 경계)도 host 가 칸을 채우면서 사라졌다.

**테스트** `PolicyRegionMap.test.tsx` 의 "높이 = 폭 ÷ 그림 비율" 단언이 옛 규칙이라 실패했다.
두 개로 나눠 새로 썼다 - 높이는 남은 화면이 정한다는 것, viewBox 가 칸 비율로 늘어난다는 것.
뒤쪽은 jsdom 에 `getBBox` 가 없어 폴백으로 빠지므로 `SVGElement.prototype.getBBox` 를
흉내 내고 끝나면 지운다. `vitest run` **380/380**, `tsc` 통과.

## 후속 - 선택을 풀 때 파도가 처음부터 다시 시작한다

**증상** 지역을 눌렀다 바다를 눌러 선택을 풀면 파도 45개가 동시에 리셋되어 화면이 움찔한다.

**원인** 선택 해제는 `raise(null)` 을 타고, 거기서 레이어 순서를 되돌리려고
`zoomer.insertBefore(seaLayer, zoomer.firstChild)` 를 무조건 부른다. DOM 에서 노드를 옮기면
그 안의 CSS 애니메이션이 전부 재시작한다 - 물마루마다 다르게 준 `animation-delay` 가
한꺼번에 0 으로 돌아가므로 45개가 같은 박자로 튄다.
(이 자리는 예전에 바다가 땅 위로 올라오던 버그를 고치며 넣은 것이라 순서 자체는 필요하다.)

**고침** 이미 제자리면 옮기지 않는다. 순서가 맞는지 먼저 보고 어긋났을 때만 끼운다.
바다는 실제로 늘 첫째라 평소에는 한 번도 안 움직인다.

**측정** 전남을 누르고 바다를 눌러 푼 뒤, 첫 물마루의 `getAnimations()[0].currentTime` 이
420ms → 1043ms. 그 사이 실제로 흐른 시간이 620ms 이므로 끊기지 않고 이어졌다(리셋이면 0 근처).
맨 앞 레이어는 여전히 `thmap-sea`, 파도 45개 유지. `vitest run` 380/380, `tsc` 통과.

함정 하나: 이 파일에는 지역 하나를 뜻하는 자체 `Node` 타입이 있어 DOM 의 `Node` 와 이름이
부딪힌다. 헬퍼 인자는 `Element` 로 받는다.
