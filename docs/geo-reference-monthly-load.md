# 건물 · 땅 지번 월 적재 (주소 채움)

일정 장소의 '주소 채움'과 '위치 찍기'가 쓰는 `geo` 스키마(건물 · 땅 지번)를 한 달에 한 번 새 판으로 바꾸는 방법이다. 설계는 `docs/superpowers/specs/2026-10-03-public-place-storage-design.md` 5절, 표 구조는 `docs/db-schema-current.md`(`0050_geo_reference`), 도구는 `backend/scripts/geo_load.py` 다.

- 서버에서 돌리는 것은 실행할 때마다 승인받는다. 이 문서의 명령은 승인 없이 서버에서 돌리지 않는다.
- 출력에는 건수 · 시간 · 파일 이름만 나온다. 연결 문자열 · 비밀번호는 나오지 않는다(`DATABASE_URL` 은 앱 설정에서 읽는다).
- 화면에는 출처가 '국토교통부 공공데이터'(GIS건물통합정보 공공누리 1유형 · 연속지적도 CC BY)로 나온다.

## 1. 받을 것

브이월드(vworld.kr) 공간정보 다운로드. **로그인이 필요해 사람이 받는다.**

| 구분 | 데이터셋 | 파일 이름 모양 | 옵션 |
|---|---|---|---|
| 건물 | GIS건물통합정보 (AL_D010) | `AL_D010_<시도 2자리>_<기준일 8자리>[(n)].zip` | '전체데이터', 최신 기준일 |
| 땅 | 연속지적도형정보 (AL_D002) | `AL_D002_<시도 2자리>_<기준일 8자리>[(n)].zip` | '전체데이터', 최신 기준일 |

- **시도 16개 전부** 받는다: `EXPECTED_REGION_CODES`(`backend/app/services/geo_reference.py`) = 11 12 26 27 28 30 31 36 41 43 44 47 48 50 51 52. 전남 · 광주는 2026-07 부터 통합 코드 12 이고, 강원 51 · 전북 52 다.
- 500MB 가 넘는 파일(경기 등)은 포털이 '선택다운로드'로 나눈다. 나뉜 조각은 이름 끝에 `(2)` 같은 번호가 붙고, 같은 파일을 두 번 받은 것과 구분하려고 내용(sha256)을 비교한다.
- 새 판이 나왔는지는 키 없는 카탈로그 API 로 알 수 있다: `https://api.vworld.kr/ned/dtmk/getDatasetList.do?format=json&ds_nm=<데이터셋 이름>`.
- **시도 코드가 바뀌면 `EXPECTED_REGION_CODES` 를 고치는 PR 이 먼저다.** 그러지 않으면 새 코드의 파일이 `unexpected region` 으로 막힌다.
- 받은 zip 은 풀지 않고 폴더에 두어도 된다(도구가 zip 안의 `.shp` 도 읽는다). 건물과 땅은 서로 다른 폴더에 둔다.
- 농지 · 임야(지목 전 · 답 · 과 · 목 · 임)는 도구가 적재에서 뺀다.

## 2. 검사 (넘길 수 없음)

구조 검사는 **하나라도 어긋나면 바꾸지 않는다**(종료 코드 3 · 4). 넘기는 옵션은 없다. 파일을 다시 받거나 고친 뒤 다시 돌린다.

- 파일 목록(`manifest_problems(files, dataset)`): 건물 폴더는 D010, 땅 폴더는 D002 만(`DATASET_OF`). 다른 데이터셋의 파일이 섞이면 `wrong dataset` 으로 막고 지역 수에 세지 않는다. 이름 모양(`unknown file name`) · 시도 코드 16개 전부(`missing`/`unexpected region codes`) · 기준일 하나 · 같은 파일 두 번(`duplicated file`) · `(2)` 조각만 있고 본 파일이 없는 경우(`part file without base file`)를 본다.
- 파일 열기: 받다 만 zip · 읽을 수 없는 파일은 역추적 대신 `<이름>: unreadable (<예외 종류>)` 로 알리고 구조 문제(종료 코드 3)로 센다.
- 좌표계: EPSG:5186 이면 그대로, 5174(2023-08 이전 판)는 5186 으로 바꿔 넣는다. 그 밖 · 없음은 멈춘다.
- 내용 중복: 이름이 달라도 `.shp` 내용(sha256)이 같으면 같은 파일을 두 번 받은 것이다.
- 품질(새 표를 만든 뒤): 같은 식별자 비율(`MAX_DUP_RATIO` - 건물 2% · 땅 1%) · 고유번호나 식별자가 없거나 잘못된 줄(`MAX_MISSING_KEY_RATIO` 0.1%) · 지목을 읽지 못한 땅(`MAX_UNKNOWN_JIMOK_RATIO` 1%).
- 법정동 이름이 건물 · 땅 어느 쪽에도 없는 법정동코드의 줄은 주소를 만들 수 없어 **새 표에서 빼고** 센다. 도구가 표마다 `법정동 이름 없는 코드 N개 · 뺀 줄 M` 한 줄을 찍는다(코드 값은 찍지 않는다). 뺀 뒤의 줄 수가 `load_run` 과 행 수 범위(종료 코드 8) 검사에 쓰인다. 2026-09 전국 판 실측: 건물 45,515줄(0.32%)이 이런 코드 183개에 속했고 땅 쪽에는 그 코드가 아예 없었다(없어진 옛 코드로 보인다 - 그 자리는 땅 레이어가 현행 코드로 덮는다). 뺀 줄이 읽은 줄의 `MAX_UNNAMED_DONG_RATIO`(1%)를 넘으면 멈춘다(종료 코드 4) - 파일이 잘못됐거나 이름 칸을 못 읽은 것이다.

도구는 표마다 한 줄을 출력한다: `새 N줄 · 고유 · 식별자 빈 줄 · 지목 못 읽음 · 도형 빠짐 · 경과 초`. '도형 빠짐'은 도형이 없거나 비어서 넣지 않은 줄 수다(품질 검사에는 아직 넣지 않았다 - 실측 뒤 정한다).

### 행 수 범위 (종료 코드 8)

새 표의 줄 수가 `ROW_BOUNDS`(건물 12,000,000~17,000,000 · 땅 16,000,000~23,000,000) 밖이면 종료 코드 8 로 멈춘다. 판이 정말 커졌거나 줄었음을 확인한 뒤에만 `--accept-row-count-change` 로 받아들이고, 다음 PR 에서 `ROW_BOUNDS` 를 고친다. **이 옵션은 행 수 범위만 넘기고 구조 검사는 넘기지 못한다.**

### 품질 검사로 종료 코드 3 이 났을 때

파일 문제가 아니라 **판의 성질이 바뀐 것**일 수 있다. 출력된 숫자를 들고 판단한다. 판의 성질이 바뀐 것이 맞으면 상수(`MAX_DUP_RATIO` 등)를 실측에 맞추는 PR(과제 2 시험을 함께 고친다) 뒤에 다시 돌린다. 넘기는 옵션은 없다.

## 3. 돌리기

빌드 대상 `geo-loader` 이미지(앱 이미지와 다르다 - pyogrio · shapely · pyproj · numpy · psycopg 가 들어 있다)를 쓴다.

```bash
docker build --target geo-loader -t th-geo-loader backend
docker run --rm --network <compose 네트워크> --env-file <backend 와 같은 env 파일> -v <받은 폴더>:/data:ro th-geo-loader \
  python scripts/geo_load.py --buildings /data/buildings --parcels /data/parcels
```

- **Windows 의 Git Bash 에서는 `docker run` 앞에 `MSYS_NO_PATHCONV=1` 을 붙인다.** 안 붙이면 `/data/...` 가 Windows 경로로 바뀌어 도구가 파일을 못 찾고 종료 코드 2 로 끝난다. 리눅스 서버에는 필요 없다.
- 로컬은 과제 14 의 명령, 개발서버 · AWS 는 과제 15 의 명령을 쓴다(둘 다 위 모양과 같고 네트워크 · env 파일만 다르다).
- 걸리는 시간 · 크기 · 최대 디스크 · WAL(2026-10-08, 로컬 PC Docker 에서 잰 값): 적재 **6,601초**(건물 끝 5,098초 · 땅 끝 6,553초, 둘 다 시작부터의 누적). 표 크기는 `geo.building` 5,046MB · `geo.parcel` 9,622MB, DB 전체 15GB, 적재 중 **최대 DB 15,097MB · 최대 WAL 1,024MB**. 들어간 줄은 건물 14,346,608 · 땅 19,406,691 · 법정동 18,846 이고, 법정동 이름이 없는 코드의 줄 45,514 + 1 줄은 두 새 표에서 뺐다. 월 갱신 중에는 새 표만큼 더 필요하다. **서버에 마련할 디스크는 최대 사용량 × 1.5 이상**으로 잡는다.
- 적재 도중 디스크 · WAL 이 모자라면 새 표 단계에서 실패하고 지금 표는 그대로다.

## 4. 잠금

적재는 DB 연결 하나를 끝까지 쥐고 advisory lock 을 건다(잠금이 그 연결에 붙으므로 중간에 연결이 바뀌면 안 된다). 도구는 끝에서 같은 연결인지, 잠금이 풀렸는지 확인한다.

- 종료 코드 5: 다른 적재가 같은 잠금을 쥐고 있다. 기다리거나, 돌고 있는 적재가 없는데 이 코드가 나오면 남은 잠금을 확인한다.
- 종료 코드 7: 끝에서 연결이 바뀌었거나 잠금을 풀지 못했다. 다음으로 남은 잠금을 확인한다.

```sql
select pid from pg_locks where locktype = 'advisory';
```

남아 있는 `pid` 가 죽은 적재의 것이면 그 세션을 끝낸다(`pg_terminate_backend`). 서버에서 하는 일은 승인받고 한다.

## 5. 실패했을 때

- 바꿔치기 **앞**에서 멈추면(종료 코드 3 · 4 · 8, 이미 `*_next` 가 만들어진 뒤) 지금 표는 그대로다. 도구가 만들다 만 `geo.building_next` · `geo.parcel_next` 도 지운다(수 GB 라 디스크가 모자란 서버에서 다음 적재가 못 돌지 않게). 그래도 남았으면 다음 실행이 맨 앞에서 지운다.
- 파일 구조 문제(이름 · 좌표계 · 열 수 없음 · 내용 중복)는 새 표를 만들기 전에 멈추므로 아무것도 바뀌지 않는다.
- 바꿔치기는 표 잠금을 5초만 기다리고 3번 시도한다(읽는 쪽이 표를 쥐고 있을 때). 모두 실패하면 되돌리고 멈춘다(종료 코드 6, `*_next` 삭제).
- 바꿔치기 중 다른 오류(데이터 오류 · 버그)는 되돌리고 그대로 올린다 - 지금 표는 그대로다.
- 종료 코드 정리: 0 성공 · 2 건물 · 땅 파일이 없음(경로 · `MSYS_NO_PATHCONV`) · 3 구조 · 품질 문제 · 4 법정동 이름 없는 줄이 1% 초과 · 5 다른 적재 · 6 바꿔치기 실패 · 7 잠금 이상 · 8 행 수 범위.

## 6. 확인

```sql
select (select count(*) from geo.building), (select count(*) from geo.parcel), (select max(finished_at) from geo.load_run);
```

컨테이너 DB 에서는 변수를 안에서 펼친다(비밀번호가 화면에 나오지 않는다).

```bash
docker exec <db 컨테이너> sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select (select count(*) from geo.building), (select count(*) from geo.parcel), (select max(finished_at) from geo.load_run)"'
```

바꿔치기가 끝나면 이전 판의 `id` 는 사라진다. 그 순간 일정에 담던 사용자는 404 `Address reference not found` 를 만나고, 화면이 안내한다(`docs/screen-feature-status-logic.md` 3-C). 담은 값은 일정에 복사돼 있어 영향이 없다.

## 7. 백업 · 복사

- 백업: `pg_dump … --exclude-schema=geo`. `geo` 는 원본 파일에서 다시 넣을 수 있고 크다. 서버의 정기 백업이 `pg_dump` 를 쓰면 이 한 줄을 반영한다.
- 로컬 정책 복사 스크립트도 `geo` 를 건드리지 않는다. 로컬에서 주소 채움을 시험하려면 로컬에서 직접 적재한다.
- 덤프 파일은 `chmod 600`, 저장소 밖에 둔다.

## 8. 운영 배포

db 이미지를 PostGIS 로 바꾼 **첫 배포**는 마이그레이션(`0050`) 앞에서 db 를 다시 만들어야 한다. 이미지가 같지 않으면 `CREATE EXTENSION postgis` 가 실패한다(계획 과제 1 Step 7 · 과제 15 Step 6). AWS RDS 는 프로비저닝 때 마스터 사용자가 확장을 먼저 설치하고, 마이그레이션은 이미 있으면 건너뛴다. 마이그레이션은 빈 표만 만들므로 **첫 적재 전에는 모든 줄이 '위치 찍기'로 나오고 `POST /api/places/locate` 는 늘 `fill=null` 이다.**
